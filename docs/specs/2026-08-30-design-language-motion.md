# 统一设计语言 + 动效规范

日期：2026-08-30
状态：已和用户确认（Q1-Q5 + 动画追加）

## 为什么做

页面是一个会话一个会话手工堆出来的，每个页面各写各的样式和动画：
对话页有 500ms 缓动和阴影，设置页只有变色过渡，菜单高亮是瞬切。
结果是"改了 A 只有 A 生效"、整体观感不一致。

病根不是框架（已经是 React 19 + shadcn/Radix，选型正确），
是缺少单一来源的设计规范和共享组件。本规范就是补这一层。

## 已确认的决策

- 视觉基准：以对话页为标杆；布局骨架沿用 New API 式（侧边栏+顶栏+内容区，见 2026-08-29-layout-newapi）。
- 存量迁移：对话/知识库/任务/设置四个页面全部迁到共享组件，不留旧写法。
- 规范范围：页面骨架、间距、动效、空状态、加载态、Toast、表单报错，一次定齐。
- 落地方式：所有颜色/间距/圆角/字号/动效时长与曲线写成 CSS 变量 + Tailwind 主题（单一来源）；
  共享组件放 `frontend/src/components/layout/`；页面层禁止手写这些样式。
- 规范文档化：产出长期开发规范文档 `docs/frontend-design-language.md`，
  根 `AGENTS.md` 加一行指引，任何会话（含外部分发会话）动前端前必须先读。
- 拆分：一个 spec，三个 ticket（见下）。

## 动效基调（对齐 Apple / iOS / macOS）

原则：能"移动"就不"瞬切"。状态变化时，元素要看得出从哪来、到哪去。

必须做到的三个场景：

1. 分段开关（对话页"询问知识 ↔ 收集资料"）：
   黑色底块从旧按钮平滑滑到新按钮，带轻微回弹。
   现状已有滑动（300ms ease-out），改为统一 spring 曲线，手感更接近 iOS。
2. 一级菜单（如"问答 → 安全事件"）：
   高亮背景从旧菜单项滑动到新菜单项，不再瞬切。
   用 motion 库的共享布局动画（layoutId）实现。
3. 页面切换：内容区淡入 + 轻微位移进入，不硬切。

通用微交互：按钮按压缩放、hover 过渡统一 150ms；弹窗/抽屉进出场统一曲线。

动效 token：
- 时长三档：快 150ms（微交互）/ 标准 300ms（滑动、切换）/ 慢 450ms（页面级进出场）
- 曲线两种：spring（位移类，带轻微回弹）、cubic-bezier(0.32,0.72,0,1)（淡入淡出类）
- 尊重系统"减少动态效果"设置（prefers-reduced-motion），此时一律降级为无动画

动画引擎：引入 `motion`（即 framer-motion，React 动画事实标准）。
按造与买原则（ADR-0004）：动画属于买的部分，边界仅限前端展示层，不许碰业务逻辑。

## 交付物

1. `docs/frontend-design-language.md`：长期开发规范（颜色/间距/圆角/字体/动效/空状态/加载态/Toast/表单报错）。
2. 设计 token：全部进 CSS 变量 + Tailwind 主题；页面层禁止写死数值。
3. 共享组件（`frontend/src/components/layout/`）：
   PageShell、SectionCard、表单行、分段开关（滑动底块）、菜单滑动高亮、空状态、加载态。
4. 引入 `motion` 依赖。
5. 四个页面迁移到共享组件，删除各自的临时类名。
6. `AGENTS.md` 加一行指向本规范文档。

## Ticket 拆分

- T1：规范文档 + 全部 token（含动效 token）。
- T2：共享组件 + 动效接入（分段开关滑动、菜单高亮滑动、页面切换过渡）。
- T3：四页面迁移 + 清理临时类名。

依赖：T1 → T2 → T3，串行。

## 验收

- 新页面只用共享组件 + token 就能拼出来，不需要新写布局样式。
- 上面三个动效场景全部"滑动/移动"，无瞬切。
- `pnpm typecheck`、测试通过，CI 全绿。
