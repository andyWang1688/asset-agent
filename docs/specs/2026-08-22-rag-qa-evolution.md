# Spec: 问答 RAG 演进（LlamaIndex）+ 检测定制 + 工程护栏

> 来源：/grill-with-docs 会话（2026-08-22）。依据 ADR 0001–0004 与 CONTEXT.md 术语。

## 问题陈述

作为本工具的用户：问答目前是单轮 + FTS5 关键词召回，没有对话上下文，检索质量停留在玩具级；敏感检测只预置了身份证/银行卡两类 PII，其余要自己写正则，且只能在设置页编辑裸 YAML；后端依赖未锁定、无 CI，回归只能靠手动发现。

## 解决方案

1. 把问答升级为专业级 RAG：引入 LlamaIndex 作为问答/检索引擎（混合召回 + 重排 + 本地 embedding），支持多轮对话记忆（历史从 chat_log 水合），保留引用标注与既有安全闸门。
2. 检测面向用户可定制：预置常见 PII 规则（邮箱/手机号等）并支持逐条启停；把裸 YAML 编辑升级为友好的规则管理界面（策略文件格式不变）。
3. 工程护栏：后端依赖锁定（uv.lock）+ CI（push/PR 自动跑后端测试与前端类型检查，合并前闸门）。

## 用户故事

1. 作为用户，我希望连续追问时模型记得最近几轮对话，以便不用重复背景。
2. 作为用户，我希望检索同时利用关键词与语义召回，以便中文口语化提问也能命中页面。
3. 作为用户，我希望召回结果经过重排，以便最相关的页面优先进入回答上下文。
4. 作为用户，我希望回答继续带 [[路径|标题]] 引用，以便核对知识来源。
5. 作为用户，我希望索引可以随时从 Markdown 重建，以便索引损坏时不丢知识。
6. 作为用户，我希望建索引默认使用本地 embedding 模型，以便 Wiki 内容在建索引阶段不出本机。
7. 作为用户，我希望未配置知识库模型时问答依然被拒绝（fail-closed），以便不产生无模型的半成品回答。
8. 作为用户，我希望问题与回答的扫描闸门原样保留，以便秘密原文永不进入模型或入库。
9. 作为用户，我希望会话历史面板与删除/置顶/重命名功能不变，以便对话管理习惯不受影响。
10. 作为用户，我希望新旧检索切换前通过同等语料的召回对比，以便升级不降低既有命中率。
11. 作为用户，我希望预置邮箱、手机号等常见 PII 规则，以便常见个人信息默认被识别。
12. 作为用户，我希望在设置页逐条启用/停用内置规则，以便按我的敏感度裁剪误报。
13. 作为用户，我希望通过表单化界面管理自定义规则，以便不接触 YAML。
14. 作为用户，我希望自定义规则仍受长度/超时/校验函数白名单约束，以便策略文件不成为攻击面。
15. 作为用户，我希望任何机器任何时间装出的后端依赖完全一致，以便环境不再漂移。
16. 作为用户，我希望每次 push/PR 自动运行全部后端测试与前端类型检查，以便回归在合并前被拦住。
17. 作为用户，我希望本地开发命令与端口保持不变，以便升级对我无感。

## 实现决策

- 问答/检索引擎采用 LlamaIndex（Python），只进入问答子系统与索引构建；安全管线、编译决策管道、凭证隔离零改动（ADR 0003）。
- 新增唯一允许的新缝：API 层与引擎之间的问答引擎接口（引擎可整体替换）；索引构建器独立可测（输入 Markdown 目录，输出派生索引，存数据目录，可删除重建）。
- 对话记忆：每次请求从 chat_log 取最近 N 轮灌入框架记忆组件；窗口裁剪/压缩由框架组件负责；chat_log 是历史唯一持久化事实源，框架不做持久化（CONTEXT.md「对话记忆」）。
- 检索路线：FTS5 → 混合召回（BM25+向量）+ 重排；embedding 默认本地模型（Ollama/sentence-transformers，BGE 系），云端 embedding 非默认。
- FTS5 与新引擎并存至对等验证通过，随后退役 FTS5 查询路径（派生索引哲学不变）。
- 检测定制：预置邮箱/手机号等规则进内置规则表；启停走既有策略的内置规则禁用通道；规则管理 UI 编辑同一策略文件，PolicyStore 校验与护栏不变。
- 护栏：uv 锁定后端依赖；GitHub Actions 在 push/PR 跑后端测试 + 前端 typecheck/lint。
- 明确不做表轮转；单进程运行约束不变（ADR 0002）；Markdown 永远是知识事实源。

## 测试决策

- 好测试 = 只测外部行为（API 响应、引擎输入输出），不测实现细节。
- API 缝：TestClient + FakeLLM，先例 tests/test_api.py、tests/fakes.py、tests/test_query.py。
- 引擎缝：索引构建器用临时 Wiki 目录测；多轮上下文组装用固定历史夹具测；召回对等用固定语料测。
- 检测缝：新规则与启停沿用 tests/test_detectors.py、tests/test_policy.py 模式；前端沿用现有 vitest 模式。
- 安全不变量：扩展 tests/test_plaintext_safety.py 的模式覆盖新引擎路径（秘密原文不进模型、不进索引构建输入之外的任何持久层）。
- CI 运行与本地同一套测试。

## 范围之外

- MCP / skill 接入（与安全立场冲突，暂缓）。
- 上下文压缩/摘要的实现（缝已预留，需求出现再做）。
- 独立向量数据库服务（索引保持派生、文件级）。
- 表轮转（已否决：用户数据由用户删）。
- 多用户/登录/远程访问（ADR 0001）。
- 编译管道 agent 化（保持现状）。
- 外部资料自动抓取入库（引入外部攻击面，另行评审）。
