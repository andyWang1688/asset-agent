# 这次要做什么：问答升级 + 检测定制 + 工程护栏

2026-08-22 讨论定稿。这份文档是本次交付的边界：做什么、怎么做已经定了、怎么算完成、什么不碰。执行者照做即可，不用再回来问"该怎么办"。

## 一句话说清楚

问答要从"能用"变成"专业"，敏感检测要让用户自己说了算，工程上补两件欠下的债（依赖锁定、CI）。

## 背景：现在的三个痛点

1. **问答太弱**：问一句答一句，不记得上文；检索靠关键词硬匹配（FTS5），换个口语化说法就找不到页面。
2. **检测不合身**：只预置了身份证、银行卡两类个人信息规则。邮箱、手机号这种常见的不管；想加自己的规则得手写正则，还得编辑裸 YAML。
3. **工程裸奔**：依赖版本没锁（今天装和明天装可能不一样），没有自动测试闸门，改坏了只能自己用出来。

## 要做成什么样

### 1. 问答升级（核心）

换 LlamaIndex 做问答和检索引擎，体验上的变化：

- 连续追问不用再重复背景——系统记得最近几轮对话；
- 口语化的中文提问也能找到页面——关键词和语义两路一起召回，再用重排器把最相关的挑出来；
- 回答照旧带页面引用，方便核对来源。

安全和兜底不变：没配知识库模型时照样拒绝问答；问题和回答照旧过扫描闸门，秘密原文永不进模型；索引坏了随时能从 Markdown 重建，知识不丢。

### 2. 检测用户自己定

- 邮箱、手机号等常见个人信息直接预置，开箱识别；
- 每条内置规则都能在设置页开关——觉得误报多就关掉那条；
- 加自己的规则用表单，不用再碰 YAML（底下的策略文件不变，护栏也不放松：长度、超时、校验函数白名单照旧）。

### 3. 工程护栏

- 后端依赖全部锁死版本，哪台机器装出来都一样；
- 每次 push/PR 自动跑全部后端测试和前端类型检查，红灯不让合并——回归死在机器上，不死在用户手里。

## 已经拍板的决策（执行者不得更改）

1. **LlamaIndex 只进问答子系统和索引构建**。安全管线、编译管道、凭证隔离一行不碰。越界就放弃引入（见 ADR 0003）。
2. **Markdown Wiki 永远是知识的事实源**。LlamaIndex 的索引和现在的 FTS5 一样，只是派生索引，可删、可从 Markdown 重建。
3. **问答引擎放在一条新缝后面**：API 层和引擎之间加接口，引擎可以整体换掉。这是本次唯一允许新增的缝。
4. **对话历史只有 chat_log 一个事实源**。每次提问从库里取最近 N 轮喂给引擎；窗口裁剪、压缩交给框架组件；框架不许自己持久化历史。
5. **建索引默认用本地 embedding 模型**（BGE 一类），Wiki 内容在建索引阶段不出本机；云端 embedding 必须显式配置才启用。
6. **新旧引擎并存过渡**：新引擎通过同等语料的召回对比后才切换默认，之后才退役 FTS5。
7. **检测定制走既有机制**：新规则进内置规则表，启停走策略的禁用通道，UI 编辑的还是同一份策略文件。
8. **单进程运行约束不变**（ADR 0002）；本地开发命令和端口不变。

## 怎么算完成

- 测试只测外部行为（API 响应、引擎的输入输出），不测实现细节。
- API 层用现有的 TestClient + FakeLLM 套路；索引构建用临时 Wiki 目录验证；召回对比用固定语料，新引擎不得低于 FTS5 基线；安全回归沿用"秘密原文不得进模型/不得进持久层"的既有测法，覆盖到新引擎路径。
- CI 跑的就是本地这一套测试。

## 不做什么（同样重要）

- **不接 MCP / skill**——和安全立场冲突，以后另议。
- **不做上下文压缩/摘要的实现**——缝留好了，真撞到长度上限再做。
- **不上独立向量数据库**——索引保持文件级、派生的。
- **不做表轮转**——对话历史是用户数据，删除由用户在界面上操作。
- **不做多用户/登录/远程访问**——永久单用户定位（ADR 0001）。
- **不动编译管道**——知识库的"自动更新"维持现状。
- **不做外部资料自动抓取入库**——外部攻击面，要做得单独评审。

## 实施顺序与拆票

顺序：护栏 → 检测定制 → 问答引擎重构。拆成 11 张带阻塞关系的票（#2–#12），每张自包含、一个上下文窗口可完成。
