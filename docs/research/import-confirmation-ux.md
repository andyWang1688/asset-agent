| [1Password：CSV 导入](https://support.1password.com/import-1password-com/) | Step 3 要求为每行选择条目类型，可 `Ignore Row`；Step 4 按条目类型给列添加标签，可跳过标签或 `Ignore Column`。导入后 `View imported items`，可 `Undo Import` 重来。 | 借鉴“按类型组织列映射、可排除、可撤销”；**不能把它描述为无需逐条确认的竞品证据**，其通用 CSV 流程明确包含逐行类型确认。 |

## 对本项目的建议（设计推论，不是竞品现有功能）

- **确认对象是处理意图，不是检测报告。** 对话内默认只显示文件、处理去向、明文说明的处理摘要，以及是否生成 Wiki；一个最终确认覆盖这些已展示的动作。完整报告保留为内部执行/审计结构。
- **调整渐进展开。** 默认不强迫审核全部命中项；只把无法自动安全处理的异常按原因聚合，提供展开、排除/修改入口。1Password 的类型/列组织方式与 Bitwarden 的定点错误反馈可分别借鉴，但“异常聚合”是本项目建议。
- **自动模式可省去预览，不能省去安全前置条件。** 识别失败、结构歧义、规则冲突不能被简洁界面掩盖；应明确阻断/暂存策略，而不是要求用户浏览大量记录替检测质量兜底。
- **确认发生在副作用之前。** 明确区分本地只读分析与持久化/远程请求/Wiki 生成；确认模式下，后者只有在授权后执行。不要把“准备”这个名称视作无副作用证明。
- **批量操作要交代失败与重复语义。** 借鉴 Bitwarden 的明确拒绝与错误定位；若支持撤销再展示撤销，不因 1Password 支持 `Undo Import` 就暗示本项目已经支持。

## 隐私与安全边界

1. Bitwarden 文档明确写明数据在发送服务器存储之前于本地加密；这说明其加密存储流程，**不是敏感数据检测、脱敏或 LLM 输入隔离的证据**。
2. 1Password CSV 文档提醒关闭备份以免备份未加密导出文件、导入后删除该 CSV；这反而说明导入流程可能接触明文，不能据此承诺“竞品不接触原始敏感数据”。
3. 本项目的人类/Vault 可见原文、远程模型只接收获准脱敏内容等边界，必须由自身数据链路与测试证明；不能由竞品 UX 类比得出，也不能用用户点击一次确认豁免。
4. 本次仅研究交互参照，未核验本项目检测准确率、表头解析、确认前副作用或安全边界实现；它们仍需独立验证。
