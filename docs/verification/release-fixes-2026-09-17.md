# 发布审查问题修复验收

日期：2026-09-17。基线：`7b6cabe`，分支：`frontend/shadcn-table`。
本记录覆盖本次审查的五项问题，不表示完整产品说明书的所有功能已经完成。

## 修复结果

1. **模型角色**：知识库、安全增强两组各自绑定添加操作；两处安全模型入口都保存 `security`，不再误激活知识模型。
2. **历史恢复**：打开历史时按会话 ID 从后端恢复，回答完成后刷新历史摘要；丢弃过期请求，水合期间禁止用旧模式提交，点击正在回答的当前会话不打断流。
3. **流式输出安全**：保留阶段提示和工具动作，但不透传模型推理原文、搜索词或路径参数。最终答案仍执行安全复扫；模型异常不回显原始响应。跨分片敏感值、自定义规则两类复现均通过。
4. **失败后重提**：失败任务保留终态，重提建立新报告、新任务；文件重用来源时不覆盖原 Raw/旧整理要求，当前任务使用独立的脱敏输入快照。复用已登记的保险柜条目，避免重复保存；整理要求中的私密引用按输入隔离。
5. **维护计划确认**：确认页面先展示经过安全检查的维护计划，可以展开页面内容。编辑报告后旧计划失效，更新计划后才能同意；接口强制检查计划 token、报告参数和 Wiki 版本。确认前不创建来源、Raw、保险柜条目或任务；确认后执行已存快照，不再请模型生成另一份计划。Wiki/安全策略发生变化时拒绝过期计划，避免覆盖新内容。

计划生成需要知识模型读取**已检查的脱敏资料**，不是读取 Private Raw；页面明确告知这一点。未确认的误报放行值也不会因为生成计划而直接送给知识模型。

## 页面链路

使用独立临时数据库、真实 FastAPI/Worker/Wiki Agent 与最新前端构建；**模型和保险柜是内存替身**，未调用用户真实模型或保险柜。

实测：虚构资料输入 → 脱敏报告及新建页面计划 → 修改预览后“同意”禁用 → 更新计划 → 确认 → 任务成功。确认前来源/任务/Raw 均为空；确认后实际 Wiki 内容与展示计划逐页一致，模型调用次数不增加。

随后只读问答正确引用 Wiki；假模型特意发送的含秘密推理片段未进入页面，处理记录只展示安全阶段提示。问答前后维护任务数不变。
